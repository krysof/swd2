# 逆向记录

## MAPA / MAPZ 世界数据库

`MAPA.EXE` 并不是可执行代码，它的 MZ 加载映像是只读世界数据库。940 字节
指针目录包含 3 个元数据槽和 466 个地点记录。每个地点记录保存地图状态字、
初始视口与角色位置、14 字节 Big5 地名，以及区域记录指针。

区域记录包含两个头字段、实体数、11 组并行的实体 word 数组（对应 RPG
`1000:10fd` 的 11 次复制），以及图块、布局、音乐、事件档案、事件字库这
5 个路径指针；总计 152 个唯一的区域记录。`MAPZ.DA*` 是同一映像的可写存档
版本，仅省略 `MAPA.EXE` 末尾的 `ffff`。`SAVE.DA+424` 保存的是指针目录中的
**字节偏移**而非逻辑下标；初始值 8 选择第 4 槽 `AREA1`。

`MAP0.EXE` 同样不是代码；其 314 字节指针目录后是 `RPG:e94` 使用的 152 组
地图触发器，共 481 条。每条 8 byte 记录把低字节行数、作为旅行解锁号的高字节、
首尾地图 word 地址和动作字打包在一起；每下一行给首尾地址加 `map_width*2`，因此
既能表示单格入口，也能表示矩形区域。`e94` 的首尾地址始终留在 16 bit `AX/DX`，
`ADD` 越过 `ffffh` 会回绕；发行数据有 7 条入口依赖这一语义，其中 `2010h` 区域的
180 行入口在第 126 行从 `4edch..4ff4h` 回绕到 `000ch..0124h`。现代匹配器也使用
`uint16_t` 逐行回绕，不再因宽位累加器漏掉这些入口。角色中心 RAP word 含 `1000h` 时，主循环会在
读取下一次输入前查询当前区域 `SAVE+408` 低 12 bit 对应的列表。普通动作低 13 bit
是 MAPZ 地点目录字节偏移，`2000h` 同时写 `SAVE+40a` 并把 `SAVE+51e+高字节` 置一，
`8000h` 则复用上述保持队列编队的相对定位。现代主循环现会跨真正的 MAP0 入口重装
区域、音乐、实体和调色板，而不是只能靠剧情 opcode 37 或旅行奇术换图。
`e94` 在普通入口装区后还会先读目的地角色中心并递归查一次 MAP0，期间没有翻页；
发行版 466 个地点有 23 个出生点正落在 `1000h` 单元上，且全部匹配动作 5..21 的
特殊记录。移植版以迭代装区保留这一链式检查，因此不会先泄漏一帧默认 BMAN，再切换
角色图集或执行出生点事件。

动作 `4001h..4015h` 进入 `f19` 的非地点分支：1..4、10、12..21 会按原固定实体号
临时令实体朝向领队并执行其普通事件，其中 10/13..15/17..21 先以 `SAVE+51a`
对应 bit 保证只执行一次；5..9/11 则按 `DS:33bf` 切换 BMAN1..5（11 保持原程序的
特殊情况：selector=5 仍重载 BMAN5）。区域 `8000h` 位在 `13b4/136c` 选择 MAN1
或默认 BMAN1，并同步十二组 X 偏移和四组三人 Y 偏移。两种入口和 BMAN3 切换均已有
真实地图端到端帧哈希。

这里的十二组并非十二名角色，而是最多四名队员各占三格的跟随队列。`dd6` 只绘制
槽 `0/3/6/9`，队员数取 `SAVE+10 + SAVE+102`（上限 4）；它从基线 -32 开始按
8 像素扫描 31 层，每层先按记录顺序绘制实体，再从末名队员倒序绘制同 Y 基线的角色。
角色帧分别取各显示槽的 `SAVE+72/+8a/+a2`，坐标和偏移取
`SAVE+12/+2a/+42/+5a`。行为 3 和 7 的实体都不会进入 `4f1c` 绘制路径。
两条精灵路径对动画值的处理也不是简单 `&1`：奇数归一为 1，偶数（尤其第 2 帧）
保持原值后再叠加精灵基号和方向。
`1e63` 每次处理方向键（包括碰撞失败）会推进每名有效队员的三个动画槽；成功移动后
`1f42` 从槽 11 向 1 倒序搬移 `SAVE+ba` 方向，并按旧方向把每格移动 2×8 像素。
视口滚动时还会先把同一屏幕位移施加到全部跟随槽，所以队列经过拐角或地图边缘时不会
重叠到领队。现代地图和事件 opcode 30..33 共用这一编队实现。

`1f42` 尾跳的 `1fa8` 还是普通地图步行的野外状态入口。区域记录第二个 word 会在装区时
进入进程内 BSS `+553`；为零时毒伤和随机遇敌计数都不推进，所以剧情 opcode 30..33
临时把它清零后不会意外触发战斗。非零区域每十个成功步检查真实队员 `SAVE+10`：状态
`0200h` 且未昏迷者扣一 HP，降到零时把整个状态字写成 `2000h`，以 `CHAIN.DSK` 显示
`DATA:373c` 警告；只要有人中毒就依次提交色号 `6b` 的整页和原地图，各停一个 70 Hz
tick。遇敌计数达到 40 后从 `RPG CS:[4f1c + SAVE+49c]` 取 word 并推进共享游标；`04h`
失败时保持 40 继续逐步取样，成功时把低五位装回计数。累计四次成功才以 `+4a0=0`
进入单进程 FIG 的区域/时间随机表。初始 `1000h` 游标在发布 RPG 代码上恰于第 75 个
成功步触发，现有地图集成测试固定了该游标、步数和模块标记。

RAP 并没有此前误判的 12-byte 固定头。`RPG:01f4` 先用 `SAVE+411` 索引文件开头的
u16 指针目录，再从记录读取 `height,width`，把 `SAVE+40f` 留在第一个单元。普通地图
目录是 `4, image_end`，记录从 4 开始，故单元基址为 8；这也解释了旧解析器为什么会
漏掉两个真实单元、把 `FFFF` 哨兵/尾字误当成所谓“106 个不可达填充”，并在非正方形
地图上交换宽高。现代解析器现按指针严格证明每条记录的尺寸和终点，129 张地图的
2,140,501 个真实 RAP 单元都引用有效图块。

`T6/ZD.RAP` 是唯一的双记录例外：目录为 `6,1234h,1a08h`，记录 0 是 93×25
滚动层，记录 1 是固定 40×25 底层，对应区域标志 `1000h`。`RPG:02af` 先复制固定层，
再把当前记录-0 视口的单元清除高四位后以非零值覆盖；`0375` 随后仍从原始记录 0
重画带 `4000h` 的图块。因此运行时现在直接合成 40×25 背景，绘制实体/队伍，再叠加
RAP `4000h` 前景，而不再先造整图后裁切。RRO 的排序位与 RAP 不同：`057f` 在角色前
绘制带 `2000h` 的六字节记录，`0611` 在角色后绘制不带 `2000h` 的记录，两者都先按
视口边界拒绝坐标再解引用图块。发行数据有 2,490 条永远位于地图外的惰性 RRO 记录；
可进入任一合法视口的所有 RRO 图块均通过字典边界审计。
地图审计还逐一证明 466 个 MAPA 地点的 `map_position` 恰等于
`cell_base + (viewport_y*width + viewport_x)*2`，40×25 视口和领队中心都在真实
RAP 尺寸内；152 个唯一区域的 822 个实体中只有四个行为 3 的发布占位记录在地图外。
其余实体的三格横向占位也都没有跨行或越过 RAP 末端。

### `SA###` 地图实体精灵

`RPG:10fd` 并不从 `DE` 目录装地图实体。MAPZ 字段 0 的高字节会经 `3e4e` 转成
三位**十进制**数，补入原程序的 `C:\\SWD2\\SA\\SA000.RSK` 模板；低字节随后保留为
基础帧号。每个区域按首次出现的高字节解压一次紧凑 `SpriteArchive`，`4f1c` 再按
`低字节 + 动画帧 + 朝向` 取帧（行为 4/5/6 不加朝向）。发行版 84 个 SA 档案共
896 帧，152 个区域引用其中 77 个；437 条可绘制 SA 实体的初始组合帧均在对应档案内。
现代世界渲染器现直接解码这套 SA 档案；旧实现
误把高字节当 `DE###.RAP` 编号，不但画错人物，在编号 70 以后还会请求不存在的文件。
`12f6` 随后会把瞬态字段 0 与 `00ffh`，但此前算出的每实体段址继续留在 `4968` 表中；
因此 opcode 3 和 39 只替换基础帧，不能把实体切回 BMAN。可达剧情中 opcode 3 就有
200 条持久基础帧写入，opcode 39 更有 155 个 SA 实体上下文直接依赖该分离。现代瞬态区域现也
独立保存已装 SA 编号，换帧不再破坏资源；重新装区后才按已写回 MAPZ 的新高字节重建。

### `DE###` 平面精灵组

`DE/DE###` 的五个伴随文件既不是普通地图，也不是 `MAN1/MEO` 的紧凑精灵
档案。`.RAP` 是以指针表开头的帧集合；每帧保存 `height,width` 的**图块网格**，
随后每个 word 选择一个 8×8 图块（值 0 输出一块透明色），而不是选择一个像素。
因此常见的 40×25 帧会展开成 320×200。`.RS1`…`.RS4` 解压后是四个 VGA
字节平面的 8×8 图块字典；图块内像素 `(x,y)` 使用平面 `x&3`，读取偏移
`y*2 + (x>>2)`。37 组资源共得到 971 帧，已由 C++
解码器逐组校验；RPG 地图实体会按 `MAPZ` 精灵字段的高字节按需加载它们。

### 地图实体与事件执行

区域的 11 组并行数组已对应到精灵编号、朝向、地图单元指针、行为、移动
延迟、X/Y 绘制偏移、动画长度、标志、事件目录偏移、动画帧。实体位置换算
复现 `RPG 1000:4fa9`：以 `SAVE+40f` 为单元数组基址、地图宽度为步长，
横向每格 8 像素、纵向每格 8 像素，并叠加各实体偏移。
`10fd` 每次装区只重建来自 MAPZ 的十一组实体字段；伴随的行为流游标、延时和漫游计数
是进程寿命内保留的固定 BSS，必须跨 opcode 37、MAP0 和旅行沿用，直到 RPG 进程结束。
实体碰撞后的 `523d` 必须先取三格占用范围内的第一条记录，再判断事件标志，不能先过滤
“可自动触发”实体。普通走路撞到行为 6 时，`5298` 会在检查 `+8 bit8000h` **之前**
把该实体行为改成 3、清除其临时占用并直接返回；发布 MAPZ 有 372 个这类记录，标志都
不是 `8000h`。它们因此会无对话地从下一张地图帧消失，而不是成为永久不可通过的障碍。
显式确认路径把 `SAVE+3802` 置一，才会越过这条隐藏分支并执行实体事件；其他行为只有
标志 `8000h` 才能由碰撞自动触发。事件目录偏移零也是 CHNA 的合法首项，不能当作
“无事件”哨兵（发布数据中有 62 条可见行为 4 记录使用它）。现代主循环现按这个顺序
处理首个占用实体。
实体查找范围也不是只看面前一格。`523d -> 52fd` 从领队中心沿朝向最多检查四格；若
整条为空，再按 `DATA:3cbf` 把起点依次偏到脚印两侧，重复两条平行的四格射线。每条在
第一个 `0800h` 静态/实体 word 停止，随后 `5269` 才按三格锚点查第一条实体记录；若
该 word 只是静态触发位，也不会继续下一条射线。四格外的 SBOUT 实体交互已有真实
CHNA 对话集成测试，避免移植后只能贴身确认。
查到实体后，`52b4` 还会保存其朝向，并按领队朝向写入相反方向（`0/3`、`9/6`），
调用 `dd6` 重画和 `6e14` 翻页，随后才进入 `5349` 执行 CHNA 事件。事件结束后原朝向
无条件写回。普通确认、带 `8000h` 的碰撞事件和 MAP0 特殊事件现在共用这一条路径；
集成测试固定了对话前新增的一帧以及事件后的方向恢复。
该恢复保存的是实体 byte offset，而不是区域对象指针；若事件中的 opcode 37 已替换
十一组 BSS 实体数组，`52b4` 返回时会把旧朝向写入目的地区域同一实体偏移。现代运行时
也把恢复值写进携带到外层装区循环的 `relocated_area`，不再误改已经脱离运行态的源区域。
同一次事件可在 opcode 37 后继续执行；`edc/10fd` 此时也替换图形、布局和调色板，
事件字库也随目的地路径重装，所以旧 DE 过场页、定位文字、钱框与灰阶页都会失效。
现代 host 会保留新的瞬态区域供
后续 opcode 3/30..33 使用，但不再把重定位前的过场层叠到目的地图上。处理器在调用
`edc` 前还把 `SAVE+459` 首字节清零以强制音乐比较不相等，因此目的区域 RIX 会在
重定位当下重启（即使路径文字相同），而不是等整条跨地图事件返回主循环后才换乐。
`0edc` 装完普通目的地后也会立即检查出生点 MAP0；发布事件的 opcode 37 目的地中，
地点 376、510、756 会直接命中特殊动作。现代 host 因而在外层 CHNA 的下一条指令前
完成 BMAN 切换或嵌套实体事件，并向外传播 FIG/退出请求。真实 CHNA5 第 16 项到地点
756、动作 15、实体 0、opcode 59 的链路已作为回归基准，防止把嵌套战斗错误延后。
旅行或读档走外层装区循环时也比较完整路径；目的音乐串为空会显式停止
旧 RIX，而不是因“没有新文件可播放”就让上一张地图的音乐无限续播。
Opcode 52 不是另一种地图重载：`5bfc` 调用 `01c9`，后者完成声音/VGA 收尾后以
`INT 21h/AH=4ch` 直接终止 RPG 子程序，且不写共享区转移标记。现代 VM 因而单独
上报程序退出，让单体运行时停止音频并以空 marker 返回启动器，而不会错误地重装当前地图。
Opcode 37 参数的 `8000h` 形式不同：`edc` 置 `SAVE+426` 后，`10fd` 在更新地图单元、
视口、十二个编队槽的坐标/方向后于 `1160` 提前返回，不复制区域实体或五个资源路径。
但 `5aa7` 在判断该形式之前已经无条件把 `SAVE+459` 首字节清零；由于提前返回不会补入
目的音乐路径，共享状态最终保留空音乐串，而当时已播放的 RIX 不会被这条定位指令停止。
这里的坐标不是把四名队员的十二个延迟槽全部覆盖成目的值：`140a` 先求目的地领队坐标与当前领队坐标的
差，再把同一差值加到 `SAVE+12/+2a` 的十二组坐标，因而保持队列相对编队和各自的
`SAVE+ba` 动画状态；普通形式才会用 `13fc` 覆盖十二组坐标并把动画状态全部置 7。
现代 VM 因而只定位且继续原事件，不触发 host 装区/外层 map reload。

Opcode 23..27/39 的参数也是这些瞬态 BSS 数组的 byte offset，但原数组各预留 100 个
word，`10fd` 和 `dd6` 只复制、处理当前 area 声明的实体数。CHNA0 动态安装的目录 740
在五实体区域里仍复用一段最长写到 byte offset 22 的十二槽编舞；超出前五槽的写入不会
进入可见实体循环。类型化移植版现在保留偶数 offset 校验，对超出声明数的固定 BSS 槽
按原可见语义忽略，而不再以 `std::vector` 越界中止这段发布剧情；五个真实槽及最终
opcode 34 写回仍正常执行。

`RPG.EXE` 数据段 `59D0` 的 62 项分派表现在每个 opcode 都有对应的可移植 VM
处理器。已确认状态语义包括实体隐藏/修改、剧情位、金钱、队伍恢复、地图内定位、
条件跳转、实体四向移动、队伍交换、物品查找/替换、商店表、背包选择、地图切换和
四种战斗请求。分支目标与实体事件字段同样是档案指针表的字节偏移。纯 VGA/演出
指令交由 `EventVmHost`。29/35/43 使用 DS:3be0 的 `DE/DE000.RSK` 模板，38 使用
DS:3bf5 的 `RX/RI000.RIX` 模板，57 使用 `VC/SP000.VOC`；49 的参数直接加到
mode-X 显存字节地址（CHNA4 的 81/161 即一/两行再加一个四像素组），53 是两个
坐标 word 后紧跟 `$$` 结束的 Big5 文字。Opcode 14 的 MENU 80..82、168..173
面板和 100..110 金钱数字也已按 22cf/2781 合成。地图中面向实体
确认时会在同一进程内查找 `MAPZ` 事件、读取 `CHNA`、用 `CHNA*.DSK` 与
`NAME.DSK` 合成 Big5 字形并显示分页对话。

Opcode 36 的帧选择还存在容易反转的顺序：`5a85..5a98` 先以当前
`SAVE+411` 合成并提交 RAP 页，再把选择器加一。现代 VM 因而会呈现
`0,1,...,n-1`，而不是先加一后跳过第零帧；每帧仍先把 `SAVE+40d` 复位到布局
基址 `SAVE+40f`。循环结束时 `SAVE+411` 已指向下一帧，但 VGA 中仍是刚提交的
`n-1`；因此前端另存最后提交的页，随后的 opcode 55 灰阶转换和 opcode 53 文字会
继续作用于该页，不能用已递增的选择器重新生成背景。

实体逐帧指令 39 的等待顺序则与普通重绘不同：`5ac7` 先在背页重组实体，调用
`5ec0` 等待 `SAVE+5a59` 的间隔，最后才由 `6e14` 翻到新页。故停顿属于旧帧，
新实体帧会在等待结束后出现；不能像 opcode 22/36 一样先 present 再延时。

Opcode 14/53/55 的钱框、定位文字和灰阶都只是直接改写当时的 VGA 页，并非持久
场景节点。`dd6` 或 `219` 的下一次全页重组（6/7/22、30..33、36、39、49）会自然
覆盖它们；现代合成器也会在这些边界清掉临时层。它们仍可跨不重画背景的对话、调色板
渐变和等待保留，但不会错误地泄漏到后续地图/实体帧。`5596` 的 opcode 14 也只调用
`22cf` 后立即返回，不读取 `5a59`；即使先前 opcode 44 设置了动画间隔，钱框本身也
不会额外等待一帧。

四个文字 opcode 也不完全同义。Opcode 18 先在 `5788` 把 `DS:359b` 设为一；
`49d0` 仍会在显式 `%%` 换页处等键，但抵达最终 `$$` 后由 `4a94` 直接清理返回，
不会播放 MENU 149..152 或再等一次确认。它常用作背包/商店之前的即时标题，现代
host 不再错误地要求玩家先关闭标题才能进入选择器。Opcode 20/46 的 `3805=1/2`
只改变逐字速度/输入路径，最终确认仍保留。`2cce` 还只在 mode 2 把 7×4 的
MENU 83..93 面板放到 `y=0`（文字 `x=10,y=13`）；普通模式位于 `y=112`
（文字 `x=10,y=125`）。正文只由字面 `##` 换行，不存在曾误判的 mode-X 列 72
自动折行；现代实现已改用真实面板精灵与这一上下布局，不再用偏移的 288×64 黑矩形近似。
`%%` 分页等待还会在当前字游标处静态叠加 MENU `91h`；最终 `$$` 则在同一位置按
`95h..98h` 循环动画。事件对话和 ITEM2/DATE2 底栏现都保留这两种不同的等待标记，
后续页重新调用 `2cce` 清空四行正文，而不会把多页文字继续附加在上一页上。发行版
ITEM2 中有 7 条说明包含共 8 个 `%%`，两页记录已有端到端回归，三页记录也由完整
语料计数锁定。

`49d0` 的框、正文和等待标记本身也是直接写进当前 VGA 页，而不是会在返回时消失的
临时宿主窗口。现代事件 host 因而保存最后实际提交的整页：后接 opcode 14 的金钱卡、
opcode 53 的定位字或 opcode 55 的灰阶会叠到对话页上；下一条 `dd6/219` 全页重组才
丢弃快照。这样 CHNA3 的“对话 -> 金钱卡”顺序不会错误地先重建裸地图。

事件入口的边界也不能按“下一个更大的目录指针”推断。`RPG:53b1` 从选中的
CHNA 指针开始逐 word 复制，直到读到 `ffff`；因此 CHNA0 目录 688 的对话会继续
落入物理相邻记录，CHNA1 目录 456 的结尾会跨过多个目录指针。另一方面 opcode
28/48/52/58/59/60 的处理器会直接跳出 `53a8` 分派循环，终止指令后的填充和共享
数据不可继续解码。现以 MAPA 的 684 个实体入口为根，并继续追踪条件分支及事件指针
改写，还会解析 235 次可达 opcode 34 MAPZ 修改，并把其中 37 次字段 9 事件指针写入
加入跨 CHNA 闭包。静态验证因而覆盖 7 个 CHNA 中 1,065 个可达入口、6,380 条命令和
60 种实存 opcode，包含原先会漏掉的 CHNA4 opcode 49 震屏和 CHNA5 opcode 51
全员转向剧情；10/11 在发行版 CHNA 中没有记录，由独立的机器码分支测试覆盖。
此外从 3,376 个 MAPA 非零实体上下文出发，把普通分支、换图、字段 9 改写及 80 个
opcode 34 动态安装上下文连同 location/entity 一起传播，得到覆盖全部 1,065 条记录的
6,862 个可执行上下文；再分别用“否/取消”和“是/一次商店重载后取消”两套确定性 host
输入执行，共完成 13,724 次入口和 62,132 条 VM
命令；任一 unsupported、异常或一万指令循环都会令发布审计失败。这不是完整通关证明，
但已把静态存在性审计提升为所有初始实体上下文的可执行性门禁。
CHNA6 目录 90 还保存了唯一一条原版数据
错误：`20,03` 把“opcode 32、向西 3 步”压在同一个 word，DOS 会越过 62 项表并
调用零地址；移植版只对这一已确认字节序列恢复其显然意图，避免剧情交互崩溃。

DE 三个入口不是各自独立加载“最近的同名资源”。Opcode 29 的 `59bc -> 0c2e`
选择一套 `.RSK/.RS1..4` 图块字典；opcode 43 从 `5b57` 先进入 `0c29` 做淡出、清页
和目标调色板安装，再落入同一字典加载器；opcode 35 的 `5a5e -> 0d3c` 才载入
`.RAP` 布局，并把 `SAVE+411` 重置为零。其后一串 35 会继续复用最后一次 29/43
选择的字典，不能按文件号向前猜测；结尾实际包含 `DE063` 字典配 `DE066/067.RAP`，
后者的图块号会超出错误选中的 `DE065`。可移植 host 现分别保存字典号和布局号，
CHNA1 目录 458 的整段结尾已能顺序打开这些非相邻组合。

Opcode 55 也不是 MSCDEX 或红书音轨调用。`RPG:5c35` 的两个 far target
`0dbf:0306/0314` 都落在 RPG 自己的加载映像：前者把 `DS:5a5c` 的 768 字节 VGA
调色板复制到私有表，后者遍历 A000 的四个 mode-X 平面：色号 `10h..1fh` 原样保留，
其余色号都按私有调色板替换为 `1fh - ((R + 2*G + B) >> 4)`。它是在 DE 动画末页上生成
反向灰阶，再让 opcode 53 叠加坐标文字。CHNA1 目录 458 有 15 次、CHNA5 目录 62
有 7 次；现代线性帧缓冲实现保留该页直到下一个 opcode 35 覆盖，并用前后帧逐像素
关系验证全部 15 次结尾转换。

Opcode 34 复现原版可写 MAPZ 地址表达式
`area + 6 + field * entity_count * 2 + signed_byte_offset`；`AD` 标签选择累加而非
覆盖模式。`5a1f` 对算出的 ES:DI 不做对齐或十一字段边界检查：可达的 CHNA2 目录 46
会越过字段 10，给紧随其后的两个 RAP 字符串指针各加 19，从 `AREA2.RAP` 切到
`AREA7.RAP`；CHNA5 目录 88 还会从一个字段 3 word 的高字节开始写入非对齐 word。
现代实现因此修改保留的 MAPZ 原始 image 后重新解析完整 area，而不是只允许写类型化
实体 vector。修改会传播到所有共享同一 area 记录的目录项，保留原版指针别名语义。
Opcode 37 在不启动新进程的情况下装入另一个 MAPZ 目录偏移，把地名、资源路径和
方向复制到共享状态，并要求 `RpgModule` 重载 RAP/RRO。它的 `5aa7` 处理器会返回
`53a8` 继续同一条事件流，并非事件终止符；可达剧情中共有 15 个入口在换图后继续
对话、移动、改旗标或操作目的地实体。移植版因此立即切换演出 host 的地图资源，把
目的地区域作为独立的瞬时 BSS 副本继续执行，再携带该副本穿过资源循环重载；
opcode 3/34 会写回 MAPZ。Opcode 3 的 `53ef` 并不只改 BSS：它重新打开 MAPZ，以
`area+6+field*entity_count*2+current_entity_byte_offset` 写当前实体，再经 `7cb6`
重写文件；因此换图后紧接的 opcode 3 也必须更新目的地源记录。Opcode 28/58 请求普通战斗；
48 和 59/60 还先写辅助遇敌字再转交 `BattleModule`。
所有这些入口以及随机遇敌都会先经过 `208f` 的四十帧退场：每帧把 Mode-X 左右半页各向
外移动两个 byte（屏幕八像素），再清空中央两个 byte，黑缝因此逐帧扩展直到整页为空。
每帧与 70 Hz VGA 刷新同步，最后一张黑页还会额外保留一个 DOS 百分之一秒。
现代 RPG host 在当前实际 VGA 快照（包括对话、钱框或 DE 页）上执行同一变换后才返回
`IF`，而不是从完整场景直接切换到 FIG。
`208f` 在擦除前还把 `DATA:3585` 当作 `FI00.RIX` 模板：普通 28/48 和随机遇敌播放
一次不循环的 FI00，58/59 先把第二位数字改成 `2` 而播放 FI02；60 写入字符 `F`，
命中比较哨兵后完全跳过转场曲。该选择与 FIG 随后按遇敌高位播放的 FI01/FI03/FI04
战斗音乐是两个独立阶段，现代单进程音频路径也不再把前者漏掉。

Opcode 19 的物品列表是变长记录；购买价格来自 ITEM 记录非对齐偏移 `+0x0b`，物品
68..72 共用状态 `+0x3e6` 的五个数量计数器。Opcode 13 的 `54b8` 清除 `DATA:3cd7`
后进入共用 `555a` 是/否选择器，只在确认左侧“是”时分支；它并不打开背包。
选择或取消后 `555a` 还会经 `dd6/6e14` 先恢复进入双卡前的 VGA 页，再让事件继续。
Opcode 17 才组合背包/商店行为：`55ce` 先设 `DATA:3cd7=1`，让 `54d5` 用 Big5
`B652/BDE6` 显示“買/賣”。左项进入 opcode 19 购买页；右项令 `DATA:3cbe=1` 反复进入
50 格出售列表，成功卖出或空格/不可卖提示后都留在列表，直到取消才通过当前实体的事件
字段 9 重载事件。`555a` 在选择后先恢复进入双卡前的页面，子页退出时 `569b` 还会提交
一张清洁地图页，再由 `53b1` 载入新记录；只有在最初的买卖卡直接取消才跳过变长商品表
并继续当前记录。`569b` 不检查字段 9 是否为零；零会照常重载 CHNA 目录首项的空
`FFFF` 记录，因此不能误作“不分支”而继续执行 opcode 17 后面的旧记录。
现代 frontend-close 不是原版的列表取消：购买或出售页关闭窗口时会直接传播 host abort，
不能再执行 `569b` 的清洁页、重载实体事件，或短暂闪回一张玩家已经关闭的地图页。
Opcode 54 的 50 次空位查找也不是普通 byte 数组：`5c2a` 每轮把 DI 增加 1，却以
word 比较当前位置与零，只有连续两个 byte 都为零才在前一个 byte 写入参数低字节；
移植版保留这一重叠 word 扫描，避免覆盖相邻的既有资料。
Opcode 42 在删除所有 `>=13ah` 的战斗临时物品之后还会调用 `3ced`；该例程用反复左移
实现 50 个 word 的稳定压紧。移植版现也在四条发布剧情路径上保留这一尾部，避免临时
物品留下的空洞改变后续背包首空格和选择顺序。Opcode 40 成功替换物品后也总会调用
同一例程；这对普通非零替换没有可见差别，但 CHNA2 的物品 75 和 CHNA5 的物品 257
都会被替换为零，因此这两条实际删除路径也必须立即压紧。
Opcode 39 也不是只改实体的 frame word：`5ac7` 写入后立即重建背页、按 `5a59` 等待
并翻页。大量剧情以 `39,8,39,8...` 逐帧播放实体动作；移植 host 现会为每个 39 提交
重建后的地图页，而不是让整段动画只在末尾偶然出现。
可移植 host 已能购买、使用、装备交换和出售；出售值及特殊数量路径按原指令处理。
ITEM 名称、类型字图、CD/AD 预览、MENU 数字和装备页 ME02 原画均直接取自原资源；
`298d` 通用列表输入中的 Down/Up/PgDn/PgUp/Home/End 六条边界也已逐分支转写：方向键
先移动面板内行，抵达顶/底行后才逐项滚动；四个整页键只修改首个可见项，始终保留
光标相对行。`2907` 会把向上/向下滚动分别暂存为 MENU 95/98 一帧，下一次绘制恢复
94/97；frame 99 的位置使用 `first*quotient+min(first,remainder)`，基线为面板
`top+14h`。这些端点闪帧和商余滑块均已按原资源重现。少数其他光标/选择动画仍待
逐像素校准。

### FIG 战斗编队与模块切换

事件 opcode 28/58 把一个参数写入共享状态 `+4a0`；opcode 48 还会先把第一个
参数写入 `+51c`，再把第二个参数写入 `+4a0`，59/60 采用相同的辅助量加遇敌号
形态。它们均返回 `IF`。新事件 VM
会把该请求交给同一进程的 `BattleModule`，不再退出 RPG 或启动 `FIG.EXE`。

`ORC.EXE` 是数据档案而非代码。其加载映像前 `0x4e4` 字节是 626 项 word
目录，索引就是上述 `+4a0` 的**字节偏移**。目录 0/2/4/6 指向四组各 60 行、
每行 9 word 的角色成长表；其余有效项归并为 550 个唯一战斗编队（610 个
非零目录入口）。普通编队依次包含 20 字节 BA 背景路径、四个 ITEM 敌人定义
号、1～5 个参战单位的定义槽和横向位置、可选 `##` 参数、以及由 `!!` 结束的
Big5 开场文字。

51 个编队带 `$$` 结束的开场文字，其中 20 个在 `$$` 后还有不属于文字的
`YN`/`NY` 控制 word（13 个 Yes/No，7 个 No/Yes）。它们已从 Big5 正文中分离成强类型
`BattlePromptOrder`；FIG 模块会用 `FIG.DSK` 显示分页开场文字，并按原版的顺序/默认项
决定进入战斗或直接返回 RPG。开场画面不再用黑底和纯色块近似：`3de8` 以 MENU
83..93 在 Mode-X `x=4,y=112` 组成 7×4 文本框，字从 `x=10,y=125` 开始；`5c98`
在 `x=44/62,y=90` 放置两个 MENU 0 选项块并叠加帧 29/8，再复用 `1e91` 的原版
调色板选中效果。ORC 全部格式化行最长 14 个 Big5 字，现代分页宽度也已收紧到原来的
224 像素，并有固定 NY 编队的整帧哈希回归。

当 `+4a0` 为零时，`FIG 1000:34c2` 按地图状态 `+408` 的低 12 位、视口 X/Y
和 DOS 百分秒在 49 组地图区域表中选择八个连续目录入口；该表已完整转写成
平台无关 C++。`+4a0` 的高两位分别选择 `FI03.RIX`/`FI04.RIX`，普通战斗使用
`FI01.RIX`，随后高位被清除。

编队中的敌人定义号按 `id*2+4` 访问 `ITEM.EXE` 目录，记录 `+2` 给出
`AD/CD###.RSK` 精灵号，`+24` 给出纵向位置。FIG 还会复制这些已确认战斗字段：
`+2c` 当前/最大 HP、`+34` 等级、`+38` 物理攻击、`+40` 先制/速度、`+48` 经验、
`+4a` 金钱、`+4c` 闪避/敏捷和 `+4e` 物理防御；字节 `+16/+17/+18/+1a/+1b`
是伤害例程使用的抗性/状态标志。当前模块以真实 BA 调色板合成
背景、敌人和 `SW/FMAN.RSK` 队伍帧，并复现 FIG 返回时清零 `+4a0`、同步四名
角色的 `+41/+43/+5f/+67` 镜像字段及返回 `OC`。

`FIG 1000:0863` 的四角色/至多五敌人先制掷骰、`1266` 的角色物理攻击/暴击倒数、
`296a` 的敌人物理攻击/闪避/附加状态已经逐指令转写。FIG 的随机函数 `2b41` 并非
普通 PRNG：它以共享 `+49c` 为游标，从 `CS:[028a+游标]` 依次读取程序代码 word，
对请求范围取余，并在 `0x2000` 回绕到 `0x1000`；`FigBattleRandom` 从原版 FIG
加载映像捕获这一窗口，所以回放会沿用相同序列并把新游标写回共享状态。
这里的回绕发生在取 word 和加二**之后**。RPG 的 `202f` 只加二而不回绕，因而可能把
边界值 `2000h` 交给 FIG；`2b41` 会先读取唯一一次 `CS:228a`，再把 `2002h` 归一为
`1000h`。现代代码窗口也保留这个额外 word，不会在合法的跨模块边界拒绝存档游标。

FIG 数据段 `+1dcc` 的 151 条、每条 20 字节能力记录现由入口的重定位 DATA 段自动
定位；同一 DATA 段 `+554..+1dcb` 的 522 条、每条 12 字节物品/怪物 Big5 名称也已
完整读取。115..150 是只会由敌方定义引用的后续能力项，不是下一区代码。角色能力表是
角色记录 `+6d` 起的 50 个 byte ID；能力标志高字节低半字节选择
`+55` 或 `+35` 资源池，`0x1000/0x2000` 选择队友/敌人目标；第 5 类则把 `cost` 低
五位按 `10/08/04/02/01` 映射到共享 `+3e6..+3ee` 五个计数器，任一用尽时清除该
能力槽。效果 `01..30` 的百分比/固定恢复、状态掩码和属性变化，`31/3b..3f` 的纯
演出返回，以及 `32..69` 的伤害、吸收、抗性、敌人状态、角色护盾和临时属性均已
成为无画面的 C++ 状态函数。普通敌方 AI 的低血量自疗、能力优先级、资源消费和目标
重掷已转写；敌方专用 `5e/5f/64/65/67/68/69/61` 状态、增益、重复增益退款并退回
物理攻击也已接入。敌人回合开始时的状态倒数、持续伤害和攻击/闪避恢复，以及角色
行动后的状态清除/临时属性恢复同样按 `0af5..0d98` 执行；角色行动前还精确检查
`status & 0x2c7e` 的禁行动掩码。

分派项 `6b` 不是独立伤害：它读取 ITEM 逻辑记录 `0x8c + ability_id` 的非对齐
`+9` word，依次执行其中两个 byte 效果，并在第一段杀死选中敌人时跳过第二段。
成长表会授予的 80/90 号组合技已经用原始 ITEM 对 `60+46`、`38+3a` 做回归测试。
战斗物品同样从 ITEM `+0/+5/+6/+7` 读取类型、消耗、目标和效果，并剥离背包 word
高四位的临时角色预约标志。
`+6` 的 `20h/10h` 只控制敌人/队员选择页，并不改写 `+7` selector 的分派类别。
因此没有目标页的 `31/3b..3f` 环境道具仍进入视觉处理器，目标位异常但 selector 为
`5e/5f/44h` 的已发布记录也继续按效果表执行，而不是被误送到 `01..30h` 支持表。

此外 `447b..478f` 并非只改 HP：它们也会改第二资源、能力资源、三个上限、状态位及
若干永久属性。每个目标事件现保存处理器完成后的 `PlayerSupportState`；呈现层在
`58a9` 对应的清洁重组点原子提交该快照，避免复活后仍画死亡图标、解异常后仍画旧状态，
或恢复 SP/AP 后资源条保持动作前数值。

支持处理器本身另有四种呈现尾部，不能复用伤害/治疗数字。普通单目标入口先调用
`5841` 重组战场与所选角色卡、翻页并等三 tick，修改状态后由 `58a9` 只重画该卡并等
九 tick；`0c..0e/12h` 的全体入口则通过 `5c79` 在可见页上执行整组旧卡九 tick、批量
修改、整组新卡九 tick，现代事件前端因此必须原子提交所有连续目标快照。`22..27h`
永久成长只执行 `5841` 和三 tick，写入 `+3` 后直接 RET，没有新卡/九 tick；`28/29h`
表项直接指向前一处理器的 RET，连 `5841` 都不会进入。上述路径均不调用 `2ac7`，不会
产生绿色恢复数字或通用三 tick 收尾。表项 `00h` 则直接指向 `4497` 的 RET：公共
pose0/pose4 与 SP001 仍会发生，但分派返回后没有任何清洁重画或附加等待。

RPG 场景道具存在同源错误：`3686/368c` 也连续两次写 `DS:379c=10`，随后 `38fe`
以 `379c` 恢复 HP、以未改写的 `379e` 恢复第二资源。`FieldActionRuntime` 现在按
`3407..3707` 保存每个入口对两个全局操作数的真实写入（包括永久成长入口写入的字段偏移），
并跨事件/地图保留；例如先用 `10h` 后复活会得到 10% HP、30% 第二资源，而不是两个 10%。
另外，百分比恢复公式 `38ab` 的四分之一加成来自 `[DS:35fc]+45`（施术/道具所有者），
并非目标角色；固定值公式 `3913` 才读取目标的指定修正字段。两条路径现已分开，向其他
队员使用道具时不会再误取目标的 `+45`。
全体入口 `12h` 还有一个容易漏掉的第三资源：`3556..358a` 清状态并调用 `38fe` 恢复
生命/体力后，`358d` 设置 `BX=55h,CX=64h` 再调用一次 `38ab`，因此每名正常队员的
奇术资源 `+55` 也恢复至上限 `+57`。场景分派现保留这第三次调用。

`MON.EXE` 也是纯数据：16 个目录 word 后紧跟一张对称的 17×17 word 矩阵，
随后是 15 组以 `FFFF` 结束的 `(定义号, 数值)` 对，共 161 对，定义号覆盖
318～481（中间存在原版保留空号）。结构和全部边界已由 `MonDatabase` 校验；
在 FIG 公式的交叉引用完成前，这两列暂以保守名称暴露，不臆测业务含义。

## 样本与架构

游戏主体是 1994 年的 16 位 x86 DOS 实模式程序。主入口 `SWD2.EXE` 很小，只负责顺序加载另外四个程序；实际功能分布在 `MEO.EXE`、`RPG.EXE`、`FIG.EXE`、`DEMO.EXE` 以及更多工具/数据程序中。主体大量直接访问 VGA `A000:` 显存、`3C8/3C9/3DA` 端口和 DOS `int 21h`，因此不能把反编译结果直接在现代系统上重新编译。

## `SWD2.EXE` 已确认流程

下面的偏移均相对于 512 字节 MZ 头之后的加载映像：

| 偏移 | 行为 |
|---:|---|
| `0000` | 用 `int 21h/AH=4Ah` 缩小自身内存块 |
| `0012` | 建立 `int 21h/AX=4B00h` 的 EXEC 参数块 |
| `0015` | 清空共享字 `4000:0000` |
| `001E` | 执行 `MEO.EXE` |
| `0036` | 仅当共享字为字节串 `MT` 时继续 |
| `003B` | 执行 `RPG.EXE` |
| `0053` | `IF`：转去执行 `FIG.EXE` |
| `0058` | `ED`：转去执行 `DEMO.EXE` |
| `0072` | `DEMO.EXE` 返回后，启动器写入 `OM`，再执行 `RPG.EXE` |
| `0078` | 执行 `FIG.EXE` |
| `0090` | `FIG.EXE` 返回 `OC` 时再次执行 `RPG.EXE` |
| `0095` | `int 21h/AH=4Ch` 退出 |

注意：表中的两个字符按内存中的字节顺序书写。例如 `IF` 的 16 位小端数值是 `0x4649`。

EXEC 参数块位于数据段 `002F`：环境段继承父进程，命令尾指向 PSP `80h`，两个默认 FCB 分别指向 PSP `5Ch` 和 `6Ch`。四个子程序名直接内嵌在启动器加载映像中。

## 子模块对共享区的使用

- `MEO.EXE` 数据段偏移 `0030` 初值为 `MT`；入口完成初始化后将它写到 `4000:0000`。内存初始化失败时该值会被改成 `1`，启动器随即退出。
- `MEO.EXE` 加载映像 `0160h` 的原始校验分支是 `75 04`（答案不符时跳过正确计数）；
  当前发行样本是 `90 90`，所以任意三次确认都会通过。合并模块现从本地 MEO 映像检测
  这两个字节并同时支持原始/补丁两种行为，未知改版不会被静默误判。
- `MEO:5a` 从校验循环返回后无条件调用 `276`：遍历保存于 `DATA:003c` 的 768 个
  DAC 分量，把每个非零值减一，等待一个 70-Hz tick 后整表写回，直到全黑才向
  SWD2 返回 `MT` 或失败标记。发行调色板最大值 63，故正常/失败出口都是严格 63 页、
  900ms；现代模块不再在第三次确认后瞬间切到 RPG。定时段只轮询 frontend-close，
  不会把已经排给 OP01 标题的方向键误吞掉。
- `RPG.EXE` 入口读取 `4000:0000`，识别 `OM` 和 `OC` 两种恢复路径。
- `RPG.EXE` 加载映像 `0B63` 处写 `ED`，随后把自身数据段 `[0000,0546)` 复制到共享区 `4000:0002`，再恢复父级栈并返回。
- `RPG.EXE` 加载映像 `205C` 处以相同方法写 `IF` 并保存状态。
- `FIG.EXE` 入口识别 `IF`；加载映像 `01BA` 处写 `OC`，使启动器回到 RPG。
- `DEMO.EXE` 不决定下一状态；返回后由启动器强制写 `OM`。

这说明 `4000:0000` 后不只是两字节命令，还保存了跨 EXE 切换的约 1,350 字节状态。现有 C++ 启动器先忠实复现控制流，后续重写存档/角色数据结构时再把该无类型内存块替换成明确结构。

## 已还原的资源格式

- 通用封装：`uint16 解压长度 + uint8 模式 + 数据 + 60 EA 00 00`；模式 0 为原样，模式 1 为 64 KiB LZ/Huffman。当前解码器已无错误验证 1,943 个文件，共解出 35,852,568 字节。
- 精灵 RSK：开头是 `uint16` 偏移目录；每项指向 `uint16 高、uint16 宽、宽×高索引像素`；目录最后一项指向 `FFFF` 哨兵，哨兵后偏移 3 是 768 字节 VGA 调色板。
- 地图 RSK：固定 818 字节，内容为 tile 数、768 字节调色板和 24 个动画控制字。
- 24 个动画字是六组 `次数、首 RGB 字节、末 RGB 字节、间隔/相位`。`5e16` 每帧给
  第四字高字节加一，高字节达到低字节间隔时把末端 RGB 三字节包回首端，并将范围内
  其余颜色向后移动；发行地图最多启用三组。现代地图主循环和剧情四向移动现在都用
  同一可移植定点相位与 RGB 轮转，不再把水面、火光等颜色冻结在 RSK 初始值。
- 世界循环 `0129..01c6` 每次按 `SAVE+406`（同时复制到 `5a59`）等待、更新颜色和
  自主实体，再以非阻塞方式采样输入；它不是菜单式的 `wait_for_input`。SDL/WASM
  空闲时现在会继续提交地图 tick，因而玩家不按键时场景也不会冻结。事件 host 初始
  帧间隔同样来自 `SAVE+406`，opcode 44 才会在剧情中覆盖它。
- `RS1..RS4`：四个 VGA 字节平面；每平面每 tile 16 字节，按“8 行 × 2 组 × 4 平面”交错还原为 8×8 的 8 位索引像素。
- 地图单元高 5 位为属性，低 11 位为 tile 编号；`0x8000` 参与碰撞，`0x4000` 决定前后景绘制批次，`0x2000` 参与角色/物件占位与排序，`0x0800` 触发特殊移动或事件。
- 共享状态中 `0x413/0x415` 是 40×25 视口尺寸，`0x417/0x419` 是地图尺寸，`0x41b/0x41d` 是视口原点；主角屏幕坐标在 `0x12/0x2a`，世界格坐标分别为 `viewport_x + ((screen_x+2)>>1)` 与 `viewport_y + ((screen_y+16)>>3)`。
- `MAN1.RSK` 含 48 个地图人物帧，按每角色 12 帧组织；共享状态 `0x72` 为帧组基址、`0x8a` 为步行动画计数、`0xa2` 为方向偏移（下/上/左/右分别为 `0/3/6/9`），精灵透明色同样是 `0xFE`。
- RAP 地图：开头是 u16 记录指针目录；每条记录为 `uint16 height, uint16 width`
  和 `width×height` 个 16 位 tile 单元，最后一个目录指针指向 `FFFF`。普通地图单元
  基址为 8；`ZD` 有 93×25 主层和固定 40×25 底层。低 11 位是 tile 编号，高 5 位
  是属性，`4000h` 把主层单元排到角色之后重画。
- RRO：重复的 `uint16 x, uint16 y, uint16 tile` 覆盖记录，以 `FFFF` 结束；色号
  `0xFE` 透明，`tile bit 2000h` 选择角色前批次，无该位选择角色后批次。
- `CHNA0..6/ITEM/ITEM2/MAPA/MAP0/DATE2` 虽带 MZ 头和 `.EXE` 后缀，加载映像实际是事件记录偏移表，并不是应在移植版启动的机器码。首字为末尾 `FF/FFFF` 哨兵偏移，第二字同时是目录字节数和首条记录偏移；重复偏移表示事件入口别名。12 个档案已全部通过边界验证，共 3,629 个入口、3,404 条唯一记录。
- 主游戏 `.DSK` 是按模块裁剪的 Big5 字库：`uint16 glyph_count`、连续的 `glyph_count` 个 Big5 双字节码、随后每字 30 字节的 16×15 单色位图。15 个字库共 11,120 个条目，解析时无需依赖操作系统字体。
- `70a6/7284` 的字码查找失败并不会跳字或抛错：循环结束会把字形序号留为零，再照常
  前进四个 Mode-X 列。各主字库的第零项都是空白 `A140`，所以缺字表现为空白但仍占
  16 像素。发行 CHNA1 语料确有一处 `B6F2` 同时不在 CHNA1.DSK 与 NAME.DSK；现代
  `LegacyFont::rasterize_or_first` 现复现这一索引零回退，RPG/FIG/通用对话不会因该条
  原始数据崩溃或把后文左移。
- RPG 事件记录是小端 16 位 opcode 流，以 `FFFF` 结束。`RPG.EXE` 数据段 `59D0` 的 62 项函数表已经定位，全部调度号均已进入可移植 VM；文字 opcode `0/18/20/46` 内嵌 Big5，`##` 换行、`%%` 分页、`$$` 结束。可变长的商店表与对象修改表也已纳入无副作用解码器；`ScriptArchive::from_records` 可在内存中构造相同指针表，用于聚焦行为测试。
- Big5 事件文字现可直接以 DSK 内嵌字形栅格化，不调用平台字体 API；空格按原版推进 4 像素，汉字推进 16 像素，行距 16 像素。
- 原版槽 1..5 每槽由 1,350 字节 `SAVE.DAn`、同后缀的可写 `MAPZ.DAn` 和
  `NAME<n>.DSK` 字库组成。`SaveSlot` 可从只读游戏目录首次复制到任意 `--save-dir`，
  再以同一事务提交三件套；
  `MapDatabase` 保留原始 MZ 映像并只在 opcode 3/34 的已验证区域 word 上原位打补丁，
  因而不会为了持久化而猜测或重排未知记录。道具效果 `6a` 的画面选择器也已按
  `RPG:4e4b` 合成：从 `RPG.EXE DATA:3a4a` 读取原始 Big5“一～五”字节，使用
  `MENU.RSK` 帧 83～93 在 `(left=4, top=112)` 画 7×4 底部通用面板、帧 141 在
  `y=141` 画槽位光标，并保留“左键在第一槽回到第五槽、右键在第五槽回到第一槽、
  上下无效”的循环输入。确认框按 `46cc` 使用帧
  0/29/8，并通过 `21de/772d` 保持选中卡原色、把另一张 64×32 卡映射到调色板表 3；
  其左右键切换是/否、Enter 提交，且原版 `4e4b` 忘记复查嵌套框的取消状态，故在默认
  “是”上按 Escape 仍会提交。消耗型存档道具同样按 `3b75` 在写盘前移除，使磁盘状态
  与原版一致。
- 单体场景道具的角色目标不再使用横向循环占位框。`RPG:265a/24b8/2fa5` 实际把四张
  48×51 的 `MENU.RSK` 头像排成方向菱形（左、右、上、下分别为队员 0～3），并在头像
  两侧/底部直接以 mode-X 平面掩码画三条资源槽；方向键直接指定绝对队员，而不是移动
  到相邻队员。`2634 -> 21de` 还是这个页面唯一的选择指示：当前角色保持原色，其余每张
  卡的 12 Mode-X 字节×51 行均经表 3 变暗。`24b8` 后半段也会叠加死亡 MENU 153、
  低血量 MENU 154 及 155..165 的十一种状态图标；前两者分别复用零色遮罩 40/64 暗化
  和 35/64 动态源色混合，不能当普通透明贴图。现有渲染与输入状态机已按这一布局、
  选择调色、状态覆盖和缺员方向屏蔽转写。
- 装备物品也按 `3f53` 先进入同一个方向头像目标器，确认角色并通过 ITEM `+04` 禁用位
  后才打开装备槽；旧实现直接默认为角色零并允许在槽画面中左右循环角色。槽号的普通
  上下移动现于 0/10 两端钳住，不再首尾回绕。装备背景已由通用矩形换成 `3fd9/46b1`
  的 `(left=0, top=0, columns=8, rows=11)` 全屏 MENU 面板，并在 `(10,40)` 不透明合成
  `ME02.RSK` 唯一的 240×134 原画。`2781` 的 `(48,0,8,1)` 紧凑面板承载当前物品名；
  `DATA:388e` 原始 Big5 槽名与 11 个装备名按 `y=13+16n` 单列呈现；各行
  `490f..495b` 会先从公共 mode-X 列 `1ch` 减去 `0ah`，所以物品名实际从 `12h`
  （72 像素）开始，而不是槽名右侧的 112 像素。帧 1 光标按

  RGB 证据。

## 当前剩余重写顺序

MAPA 的全部非零实体事件入口现还会经过静态可达图审计：7 个 CHNA 档案的 684 个入口
闭包覆盖 1,065 条记录、6,380 个命令和 60/62 个调度号。分支、换图后的当前实体事件
重写、物品/队员条件跳转，以及 235 次 opcode 34 中 37 次跨档案字段 9 写入都会加入
闭包；只有发行资料根本未使用的 10/11 不在图中。CHNA1 记录 189 中“查找物品零”后
永远不会采用的奇数目标 287 被单独计数，新增任何未解释奇数目标、动态加法事件指针或
图规模变化都会令回归失败。同一命令还会运行上述 13,724 次实体上下文执行门禁；它不能
替代逐帧通关回放，所以世界运行时状态仍保持 `in_progress`。

1. 完成 FIG 剩余信息卡和特殊状态画面的像素差分；
2. 对 RPG 背包/装备、奇术、旅行和存档槽界面的其余状态做 DOSBox 逐像素差分；
3. 核对其余平台依赖输入的替代边界；
4. 扩展 DOSBox/原版逐场景差分和完整通关回放，消除所有通用居中或占位画面；
5. 在每个平台后端做长期运行、存档往返和音画时序测试，直至不再存在近似行为。

原生 SDL 输入现另有使用 dummy 视频/音频驱动的可执行边界测试：方向键、翻页/Home/End、
Enter/Esc、手柄十个数字按钮、摇杆启停滞回、逐字轮询，以及 frontend-close 保留队列
都通过真实 `SDL_PushEvent` 进入与发布程序相同的 `SdlPlatform`。键盘、十字键和摇杆
分别还执行“一次按下、69 个世界帧、一次松开”的电平测试；这能锁住桌面映射、连续移动
和关闭事件不误消费动作的语义。真实浏览器 DOM/IDBFS 与物理手柄矩阵仍必须另行执行，
因此 portable-input 门继续保持 `in_progress`。

Web 触摸层重新暴露上、下、左、右与 ESC/回车六键；世界主循环直接在每个已呈现帧读取
持续按下状态，所以一秒 69 次 `poll_input` 会得到 69 次同一方向，而不是依赖浏览器的
键盘自动重复。阻塞式菜单仍按原有 180 ms 首延时、85 ms 间隔移动，快速点按另有单项
队列保证按下/释放都发生在两帧之间时不会丢失。ESC/回车保持单次触发，避免一次长按跨过
多个确认页；指针取消、触点结束和窗口失焦都会清除持有状态，不留下粘住的移动方向。
WASM 的阻塞输入循环还必须在每次 `emscripten_sleep(10)` 恢复后重新读取这份 JS 状态：
触摸方向不会产生 SDL 事件，旧实现只在进入 `wait_for_input` 前采样一次，手指若在菜单已经
等待后才按下便永远不可见。现在每次协作式恢复均先取快速点击/保持电平，再检查 SDL 队列。

五个便携槽实际是 SAVE/MAPZ/NAME 三件套，而不是两件套：原版 `4ce6..4d29` 写
`SAVE.DAn`、`MAPZ.DAn` 和 `NAME<n>.DSK`，`4c16..4c73` 读三者并把槽位 NAME
复制为活动 `NAMEQ.DSK`。`SaveSlot` 现在先完成三份临时文件，再安装 `SWD2SLOT2`
事务标记，按 NAME→MAPZ→SAVE 固定顺序替换；若进程在任一段之间退出，下次 open 会
按仍存在的临时文件向前完成，而没有标记的预备文件一律丢弃。旧前端留下的
`SWD2PAIR1` 中断事务仍能恢复，已有 SAVE/MAPZ 而没有 NAME 的旧存档根目录会只补入
发行槽的姓名字库，不覆盖玩家世界状态；该升级同样先写 `.swd2-slotN-name.tmp` 再原子
替换，绝不直接把可能中断的复制写进 canonical NAME。回归模拟了无标记、旧二件事务和“NAME/MAPZ
已换而 SAVE 未换”的三件事务中断点。浏览器仍需通过真实 IDBFS reload runner 证明
这套文件级恢复在持久化层重启后有效。

原版画面捕获工具现在也拒绝伪证据：DOSBox-X 只要非零退出，就算已留下 AVI 也立即失败；
`ffprobe` 报告的时长或帧数非正同样失败，请求 PNG 抽帧却没有生成任何帧也不能写 manifest。
这堵住了强制终止的 DOSBox 进程留下零时长/残缺 AVI，却被登记成可重复 RGB 基准的漏洞。

前端可选的退出检查点以前还有一个跨启动分支的配对错误：入口先打开命令行默认槽，`OM`
随后把核心世界替换为 `SAVE.DAQ/MAPZ.DAQ` 并保留刚编辑的活动 NAME，但退出只把新
`SharedState` 交给旧 `SaveSlot::save`，于是会把新游戏 SAVE、启动槽旧 MAPZ/NAME
拼成合法却互不对应的一组。现在保存明确接收核心当前的 MapDatabase 和姓名字库，提交后
还以落盘结果更新槽内快照。集成回放故意从槽 3 开始新游戏，退出后逐字节重算
SAVE/MAPZ/NAME FNV，必须分别等于回放最终状态的
`1693cf52a3bbdad7`/`827f0f1b725a0958`/`e3d2853e2676513b`；严格回放若尚有
未消费输入则在写盘前失败。
Record 回调也会把前端活动槽切到玩家确认的编号；否则先读槽一、Record 到槽四再退出会
额外把同一状态覆盖回槽一。另一条隔离回放走完全相同的菜单输入但加 `--no-save`，要求
槽一仍与发行文件逐字节相同且槽四根本没有生成，锁住“禁用所有写盘”而非只禁退出写盘。
Web 壳的 `?idbfs-self-test=TOKEN` 也新增两页隔离执行回归：第一页把唯一探针写入模拟
IDBFS、提交并设置 session token 后只触发一次 reload；第二个全新 JS/内存文件系统从
同一持久层恢复，逐字节比较、删除探针、再次提交并只在全部成功后设置
`data-idbfs-self-test=pass`。这能拒绝壳层探针自身的伪通过，但仍不能代替真实浏览器
IndexedDB 重启矩阵，所以存档门保持 `in_progress`。

`RPG:10fd` 的换图装载器只覆盖来自 MAPZ 的十一组实体字段；它没有清零 `3cba` 的
代码流游标，也没有清零 `4260/4580/4648` 的逐实体延时和横纵游走计数。它们是整个
RPG 进程寿命内保留的 BSS，而不是每张地图的新状态。因此普通 MAP0、opcode 37 和旅行
换图后，同一数组下标会继承前一地点的剩余延时/游走边界，随机代码流也从原位置继续；
只有离开 RPG 进程再重新进入时才恢复零。现代单进程调度现把这条“原进程边界”显式保留，
不再在 C++ 外层地图循环中误清空这些字段。原数组还是固定容量：先到实体多的地点、再到
实体少的地点不会销毁高下标，之后回到多实体地点仍能看到旧值；C++ 的动态容器因此只扩容
而不随当前实体数缩小。

完整回放输入不再受命令行长度或“同一队列被哪个 API 先读”影响。`replay_input` 的文本
格式可把每一步标为 WAIT（交互阻塞）、POLL（普通非阻塞）、TEXT（跳字）或 FRONTEND
（只允许 NONE/QUIT），并用 `*次数` 压缩连续移动/空 tick。严格 `--run-replay` 遇到
阻塞边界不符、百万次无进展轮询或未消费尾部都会失败；`--trace-output` 同时记录帧/调色
板链及每页独立摘要、每次输入前的 SAVE/MAPZ 状态点、音频载荷链、累计延时、最终状态、
模块切换和每类输入调用。另有统一 timeline 把每次页提交、输入消费、音乐/语音/停止和
正延时锁到累计毫秒位置，因而不能用“总延时相同”掩盖音频或帧提交点被前后移动。当前 CTest 用
三个 WAIT:CONFIRM 通过 MEO 后，烟雾回放在 OP01 选择继续、确认第一槽和默认“是”，
最后以 POLL:QUIT 从世界页退出；它只证明 MEO→RPG 标题/读档边界及回放基础设施可执行，
不能冒充完整通关证据。
另一个边界锁定检查点只发送四次 WAIT:CONFIRM（MEO 三次和标题默认“开始游戏”）、一次
POLL:CONFIRM 跳过 DEMO、一次 POLL:QUIT 退出开场事件后的世界页。其 trace 必须严格为
`MEO(--→MT), RPG(MT→ED), DEMO(ED→--), RPG(OM→--)`，共 230 页（37 次直接写页）、
